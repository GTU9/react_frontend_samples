# 샘플 리디자인 작업 기준

## 목표

24개 샘플을 단순한 시각 효과 전시에서 실제 상품, 작업, 글, 사진을 중심으로 한 화면으로 바꾼다. 기존 경로, 독립적인 샘플 구조와 글 작성/조회 등 클라이언트 기능은 유지한다.

## 조사와 판단

- [InterfaceKit: What makes a website look AI-generated?](https://blog.interfacekit.io/what-makes-a-website-look-ai-generated): 일반적인 색상 하나로 제작 방식을 판정할 수는 없다. 제품의 구체성이 없는 구성과 반복적인 카드가 이번 개선 대상이다.
- [It's Nice That](https://www.itsnicethat.com/): 문화 매체의 주제별 탐색, 사진과 기사 제목의 위계를 참고한다. 기사 원문과 브랜드는 복제하지 않는다.
- [The Guardian](https://www.theguardian.com/international): 뉴스의 정보 위계와 섹션 구성을 참고한다.
- [MUBI](https://mubi.com/en/films): 작품 중심 탐색과 편집된 영화 컬렉션을 참고한다.

## 실행 계획

1. 기존 렌더링 테스트를 기준선으로 확보한다. 변경 전 26개 테스트 통과.
2. 분야별로 서로 다른 정보 구조, 타이포그래피, 팔레트, 사진의 역할을 정한다.
3. 샘플 내부에서 TSX, CSS, 목업 데이터를 수정한다. 장식용 그라데이션과 빈 이미지 대체물은 실제 이미지/콘텐츠로 교체한다.
4. 갤러리를 작업 목록 중심으로 정리하고 설명과 미리보기를 새 화면에 맞춘다.
5. 빌드, 전체 렌더링 테스트, 핵심 상호작용, 24개 샘플의 데스크톱/모바일 레이아웃과 이미지 로드를 검증한다.

## 디자인 규칙

- 전체 화면을 같은 템플릿에 넣지 않는다. 운영 도구는 밀도 높은 작업 화면, 상점은 카탈로그, 매체는 편집된 지면이다.
- 광택, 유리, 발광 구체, 목적 없는 배지, 근거 없는 고객사 로고와 성과 수치를 제거한다.
- 사진은 로컬 자산으로 제공하며 출처와 용도를 분야별 문서에 기록한다.
- 반복 아이템 외의 페이지 구역은 카드로 감싸지 않는다. 카드 모서리는 최대 8px.
- 한글 줄바꿈, 명도 대비, 키보드 탐색, 모션 감소 설정을 고려한다.
- 뉴스/금융 데이터, 주문과 게시물은 실제 서비스에 연결되지 않은 로컬 샘플임을 필요한 지점에 명시한다.

## 검증 환경

Browser plugin 스킬이 제공되지 않아 저장소에 설치된 Playwright Chromium으로 검증한다. 개발 서버는 `http://127.0.0.1:5173`를 사용한다.

## 검증 결과

- `npm run build`: TypeScript 프로젝트 참조 검사와 Vite 프로덕션 빌드 통과.
- `npm test`: 36개 통과. 24개 샘플과 갤러리 렌더, 기사 보관/검색, 블로그 6종의 작성·미리보기·발행·조회 포함.
- `npm run thumbnails -- http://127.0.0.1:5173`: 24개 실제 화면 캡처 갱신.
- Playwright: 갤러리와 24개 샘플을 1440x900 / 390x844에서 확인. 50개 화면 모두 콘솔 오류·경고 0, 빈 화면·가로 넘침·깨진 이미지 0. CSS 배경 이미지도 검사.
- 정적 스타일 검사: 24개 스타일시트 모두 해당 `.sample-<slug>` 아래로 범위 제한.
- 수동 화면 검토에서 발견한 모바일 채팅 패널 잘림, CRM 추가 버튼 축소, Inkwell 제목 폭, 보관함 보조 목록 필터 누락을 수정.
- Playwright 상호작용 검사: 장바구니 수량/제거, 거래 생성/편집, 작업 이동, 사진 필터/라이트박스, 영화 소개 창 저장/Escape 닫기, 채팅 전송, 음량/진행 범위 입력을 확인.

전체 보고서와 화면은 gitignored `.omc/visual-qa/`에 저장한다. 최종 갤러리 비율, SoftDeck 버튼 문구, Lumiere 제목 줄바꿈 재검증은 `.omc/visual-qa-final/`에 별도 기록한다. 별도 lint 스크립트는 없으며 타입 검사, 테스트, CSS 범위 검사, `git diff --check`를 사용했다. 개발 모드 테스트에는 기존 React Router 차기 버전 안내 경고가 남아 있다.

## 남은 범위

백엔드·결제·메일 발송·음원/영상 스트리밍은 구현 대상이 아니다. 모든 데이터와 편집 상태는 로컬 데모이며 새로고침 시 초기화된다. 자동 레이아웃 검사는 모든 접근성 기준의 완전한 감사를 대체하지 않는다.
